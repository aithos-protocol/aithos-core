# 1 — Identity and keys

> **Status: DRAFT.** Who holds what. The complete key inventory of the system fits in
> this one page — that is a design goal, not an accident.

## 1.1 The owner's master seed

`S` — 32 CSPRNG bytes, generated at identity creation. From it, by derivation:

```
root_sign   = ed25519_seed( derive("aithos-core/v1/root-sign", S) )    — identity root
sphere_pub  = ed25519_seed( derive("aithos-core/v1/sphere/public", S) )
sphere_cir  = ed25519_seed( derive("aithos-core/v1/sphere/circle", S) )
sphere_self = ed25519_seed( derive("aithos-core/v1/sphere/self",   S) )
owner_kex   = x25519_sk(    derive("aithos-core/v1/owner-kex", S) )
```

- **root_sign** controls the DID document and issues/revokes first-level mandates.
- **Sphere keys** sign zone content and gamma entries authored by the owner, one per
  zone (accountability per audience, carried over from Aithos v0.x).
- **owner_kex** is the recipient key of the owner's line in every header (I3).

`S` is the only thing to back up. The **recovery artifact** contains `S` (mnemonic or
file); the DID document pins the public halves. Devices hold wraps of `S` sealed to a
per-device X25519 key (`device.json`, one wrap each); adding/removing a device touches
that one file. Losing every device and the recovery artifact loses the identity and
the encrypted content — deliberately, as in every prior Aithos version.

## 1.2 Grantee keypairs

A grantee (agent, device, person) owns exactly **one Ed25519 keypair**, generated by
or for it, whose public key is named in its mandate. Its X25519 counterpart (standard
Ed→X conversion) receives its header lines and sealed payloads. There is no other
grantee material: no trousseau, no epoch keys, no keybag. **A grantee's complete
portable state is `{keypair, mandate file}`** (§08.4).

The keypair is capability-bearing, not registered in the DID document; its authority
is exactly its mandate chain, its lifetime exactly the chain's validity.

## 1.3 Node keys

Every protected node has a current **DK**: 32 CSPRNG bytes, random at node creation
and at each rotation, identified by `(node_path, key_version)` with `key_version` a
monotonic integer. DKs exist only inside headers (sealed) and in RAM. Below a DK,
content keys derive one-way:

```
K(child) = derive("aithos-core/v1/" + child_label, K(parent))
```

so holding a node's DK yields its entire subtree, present and future; nothing else.

## 1.4 DID document (minimal carry)

`did:aithos:<multibase(root_sign.pub)>`. The DID document lists: root key, the three
sphere public keys, `owner_kex` public, revocation-state pointer (§06.5), and the
bundle's canonical location(s). It is signed by root_sign and versioned by the same
edition chain as the bundle. Grantee keys never appear in it.

## 1.5 Key inventory (complete)

| Holder | Material | Mutable? |
|---|---|---|
| Owner | `S` (+ derived signing/kex keys, recomputed) | never (root re-key = new identity epoch, §10.4) |
| Device | one X25519 device key + wrap of `S` | replaceable per device |
| Grantee | one Ed25519 keypair | **never** (I2) |
| Node | DK per (path, key_version) | rotated by authorized revocations |
| — | there is no other key material in the system | — |
