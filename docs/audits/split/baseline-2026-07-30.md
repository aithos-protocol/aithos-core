### Anomalie préexistante relevée : clippy rouge sur Linux

`rust/crates/aithos-cli/src/custody.rs:7` : `const KEYCHAIN_SERVICE` n'est
utilisé que sous `#[cfg(target_os = "macos")]` (l. 139). Sur toute cible non
macOS — **dont `ubuntu-latest`, l'OS du job `clippy` de `ci.yml`** — la
constante est du code mort et `-D warnings` échoue :

```
error: constant `KEYCHAIN_SERVICE` is never used
 --> crates/aithos-cli/src/custody.rs:7:7
```

Ce n'est pas un artefact du chantier : l'arbre de départ porte ce défaut.
Correctif minimal appliqué en commit isolé du lot SPL-0 (ajout du même
`#[cfg(target_os = "macos")]` sur la constante), aucun comportement modifié
sur aucune plateforme.

## Le harnais `scripts/split-baseline.sh`

Rejoue `cargo test --workspace`, parse les compteurs par harnais (y compris
les blocs `[Summary]` cucumber) et échoue sur toute baisse, tout échec, tout
harnais manquant et toute variation du nombre de `@wip`.

**BDER-011 couvert pour ce chantier** : le harnais cucumber d'`aithos-bundle`
appelle `filter_run` sous `harness = false` et sort 0 même en échec. Le script
ne fait donc jamais confiance aux codes de sortie : il compte. Preuves par
l'échec rejouées le 2026-07-30 :

- baisse simulée d'un compteur unit (`20 → 19` sur `aithos::cli_surface`) → rouge ;
- scénario cucumber en échec simulé (`836 passed → 835 passed, 1 failed`,
  code de sortie inchangé) → rouge ;
- dérive `@wip` simulée (36 ≠ 35) → rouge.
