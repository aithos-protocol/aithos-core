## 1. Levels (§09.4) claimed by this repository

Spec §09.4 defines three cumulative levels; the vectors gate each claim.

| Surface | Core reader | Core issuer | Agent host |
|---|---|---|---|
| Rust crates (`aithos-core` + `aithos-bundle`) | **claimed** | **claimed** | **claimed** |
| CLI (`aithos-core` binary, `aithos-cli`) | **claimed** | **claimed** | **claimed** |
| Docker image (`docker/Dockerfile`, the same binary FROM scratch) | **claimed** | **claimed** | **claimed** |
| npm package `@aithos/core` (`aithos-wasm`) | not yet | not yet | not yet |

- **Core reader** — resolves the DID, opens headers it holds lines for,
  derives, decrypts, verifies editions + gamma, enforces the fork rule
  (§02.6) fail-closed: `verify_links` refuses an unresolved fork; a
  resolution is accepted only from the nearest common manager
  (`resolve_fork`, authority via `dir_covers`). Exercised end-to-end by
  the K walkthrough's cold replay.
- **Core issuer** — mint/delegate/revoke + header rotation under §05.5
  authority; §05.3 pre-flight refuses the over-wide sub-mandate; an
  unauthorized rotation is refused (smuggled-recipient check, G).
- **Agent host** — action execution under tier-X/C constraints (budgets,
  windows, profiles, obligations §04.12) with mandatory gamma action
  entries; kinds are imposed by the operation, never chosen by the agent
  (surface rule, tested by `cli_surface.rs`).

**The npm package is a surface stub, by decision (2026-07-11).** It packs
the existing thin WASM binding (`genesis_pubkeys`) locally — proof that
the canonical core compiles to WASM unchanged and is importable from
node. It claims NO conformance level yet: extending the binding to the
offline verifier surface ("Core reader" over JSON inputs) is a dedicated
post-K pass. It is never published to a registry; `npm pack` only.

## 3. Performance (§09.3) — measured

Harness: `cargo bench -p aithos-bundle` (criterion, `benches/perf.rs`).
Machine: the K-pass build container — x86_64, 2 vCPU, 8 GB RAM
(§09.3 assumes "a laptop"; this box is smaller, numbers are conservative).
Statistical rows run on `MemStore` — the measured costs are crypto +
serialization, which dominate; the two 1M rows run on a synthetic
in-memory tree (the operations are O(log n) path work by design).

| §09.3 operation | Target | Measured (median) | Verdict |
|---|---|---|---|
| grant (mint cert + N header lines) | < 20 ms | 270 µs | **pass** (74×) |
| delegate (sub-mandate) | < 20 ms | 223 µs | **pass** (90×) |
| add a reader to an existing node (1 line) | < 5 ms | 206 µs | **pass** (24×) |
| verify a depth-2 chain (offline) | < 10 ms | 182 µs | **pass** (55×) |
| revoke rung 2 (rotate headers, no re-encrypt) | < 50 ms | 217 µs | **pass** (230×) |
| revoke rung 3, 1000-section zone (re-encrypt) | < 5 s CPU | 898 ms | **pass** (5.6×), single-thread |
| read a section (open header → derive → decrypt) | < 2 ms | 332 µs | **pass** (6×) |
| gamma full verify, 10k entries | < 200 ms | 538 ms | **over on this box** — see note |
| inclusion proof verify (1M sections) | < 1 ms | 6.3 µs | **pass** (158×) |
| state-root update on one edit (1M sections) | < 1 ms | 6.3 µs | **pass** (158×) |

**Note — the one miss.** Full gamma verify re-checks every Ed25519
signature: ~50 µs each on this 2 vCPU container × 10k entries ≈ 500 ms,
which is the measured number. The §09.3 target (< 200 ms) assumes a
laptop-class core (~20 µs/verify — an M-series is near or under target).
Two honest paths, deliberately NOT taken unilaterally at step K:
`ed25519-dalek` batch verification (~2-3×, additive, no wire change) or a
rayon-parallel scan (the spec already calls rung 3 "parallelizable").
Recorded here; decision owner: Mathieu.

## 4. Packaging (plan §K, bounded)

- **Docker** — `docker/Dockerfile`, base pinned `rust:1.96-alpine`,
  `--locked` build of the repo content alone, final stage `FROM scratch`
  with the single static binary. Built and smoke-tested in the K pass;
  size recorded below. The image is tagged locally (`aithos-core:0.1.0`)
  and pushed nowhere.
  - measured size: **4.11 MB** (target < 15 MB) — LTO + strip, static musl
  - smoke: `--help`, then a full round-trip in a mounted volume (init →
    section-add → edition-publish → edition-verify OK → log-verify OK)
- **npm** — `wasm-pack build rust/crates/aithos-wasm` then `npm pack` of
  the generated package: `@aithos/core@0.1.0`, local tarball only. Smoke:
  a node script imports the tarball-installed package and checks
  `genesis_pubkeys` against the frozen `a1-genesis` vector byte for byte.
  - importable: **yes** — installed from the local tarball in a scratch
    project, imported from node 22 (ESM over the nodejs target)
  - vector cross-check: **byte-exact** (`docker/npm-smoke.mjs`)
