## Scope and decision

This correction implements only the Provider remainder of AID-001 under the
binding §01.4/§10.4 decision:

- DID documents remain root-signed and pass strict Core verification;
- succession signs only a separate `EpochTransition`;
- a new root means a distinct successor DID;
- succession-signed same-DID `did.json` is invalid;
- any future epoch-acceptance surface must verify the complete previous
  document / transition / successor document triplet through Core before
  committing persistent state.

AID-002 and AID-005 remain unchanged and verified within the pilot scope.
AID-003 and AID-004 were not addressed.

## Protocol boundary retained fail-closed

The Provider exposes only `did.json` and lacks:

1. a canonical artifact URI or request form for the complete epoch triplet;
2. a control-plane operation binding the successor DID;
3. an atomic cross-DID commit for transition plus successor document;
4. CAS, replay, and single-use semantics for an epoch change.

Implementing an acceptance route would therefore invent wire and storage
semantics. This candidate instead removes the invalid same-DID replacement
path. A future public route must define the four contracts above and call Core
`EpochTransition::verify_succession(prev_doc, next_doc)` before committing any
part of the transition.

## Candidate implementation

- `artifacts::deposit_did` parses the strict typed `DidDocument`, checks
  canonical JCS and path identity, calls Core `DidDocument::verify`, and then
  uses atomic `ObjectStore::put_once`;
- first storage and byte-identical retry succeed, while a byte-different
  same-DID document returns `immutable_conflict`;
- succession-signed `did.json` fails strict Core verification before storage;
- Provider scenarios read persistent storage after refusal and prove either
  genesis absence or byte-exact preservation of the original document;
- P9 removes the obsolete `did_rotation_ok` / `did_rotation_root_signer`
  semantics, adds explicit same-DID refusal cases, and adds a root-signed
  unsupported-version genesis refusal;
- Provider documentation and the public Identity audit record the missing
  canonical epoch-transport contracts without claiming a public transition
  implementation.

## P9 generation provenance

The committed legacy P9 generator imports PyNaCl, which was not installed in
the execution environment. Its direct run failed on that missing dependency,
and fetching the package was denied by execution policy. To avoid broadening
the candidate with a dependency migration, the deterministic P9 file was
regenerated with a temporary equivalent Ed25519 adapter backed by the already
installed `cryptography` package; that adapter was not committed.

The independent committed `verify-p9.py` was migrated to `cryptography` and
successfully recomputed all 58 checks over 32 cases. The real Provider binary
then replayed the committed P9 wire cases exactly. The final committed
`gen-p9.py` itself was not directly executed in this environment; this is a
dependency limitation, not presented as a green generator gate.
